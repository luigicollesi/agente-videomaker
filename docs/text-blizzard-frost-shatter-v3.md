# Blizzard — Frost Shatter V3: timeline-driven VFX

Contract: [docs/vfx-timeline-timing-contract.md](../../../../../docs/vfx-timeline-timing-contract.md) and [OpenFilm VFX timeline skill](../../../../../.agents/skills/openfilm-vfx-timeline/SKILL.md).

## Timings

- **Entrance time:** `--blizzard-in` (default 2.4 s).
- **Exit time:** `--blizzard-out` (default 3.3 s).
- **Total:** the effective timeline clip end, supplied by OpenFilm in `--clip-length`; this is a hidden, machine-managed `data-props` entry, not a user-facing total duration control.
- **Hold:** `max(0, total - entrance - exit)`. Exit takes priority on an overfull clip: `exit=min(requestedExit,total)`; `entrance=min(requestedEntrance,total-exit)`.
- The HTML deliberately **does not expose `window.film.duration`**, to prevent the native-duration clamp in `sourceAt()`.
- `window.film.frame(t)` renders absolute source time and declares `frameReadsOverrides:true`.

The initial library duration is **10.5 seconds** as metadata only. Extending to 20 seconds with entrance=2 and exit=3 must yield hold 2–17 and exit 17–20; shortening to 8 seconds yields hold 2–5 and exit 5–8.

## Trim/split

The player time is **source time**. For a trimmed/split clip `time:[start,end]`, the end is still `end` seconds on that clock; the exit is anchored at `end-exitTime`. A clip with a nonzero `start` does **not** automatically restart formation; preview and export must be verified separately for split/trim operations.

## Library updates

The new built-in bundle id is `text/text-blizzard-frost-shatter-v3` and the new internal filename is `blizzard-frost-shatter-unbounded.html`. OpenFilm copies bundles to each project once. Existing V2 clips remain untouched and are not upgraded automatically; replace them by inserting V3 and transfer text/art parameters as required.

`preview.mp4` is a fixed thumbnail sampled from an earlier default animation. Live clip output is generated by the HTML; it is not encoded by the thumbnail.
